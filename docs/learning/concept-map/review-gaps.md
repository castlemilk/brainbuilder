## CR 001 — Big O keyed answer does not answer the question

Tracked follow-up: [BB-LRN-011 — issue 72](https://github.com/castlemilk/brainbuilder/issues/72).

**Exact source:** [conceptLessonProfiles big-o-as-shape](https://github.com/castlemilk/brainbuilder/blob/abf70fa012356038ffa5a2c4092584d452724e5e/packages/courseware/src/index.ts#L380-L409), constructed by [conceptLesson](https://github.com/castlemilk/brainbuilder/blob/abf70fa012356038ffa5a2c4092584d452724e5e/packages/courseware/src/index.ts#L936-L968). Course `algorithms-data-structures`; lesson `big-o-as-shape`; generated block `big-o-as-shape-check`.

**Reproduction:** construct the course, find that block and inspect `question`, the option whose ID equals `correctOptionId`, and its feedback. The question asks what Big-O helps compare. The keyed option ID is `name-invariant`, whose profile label says “Name the invariant and preserve it.” Selecting it is marked correct, while the feedback describes growth in work as input size changes.

**Expected:** the keyed answer should answer the growth-comparison question under a stated cost model. **Actual:** the correct label refers to a different construct; the feedback does not make the labelled answer responsive.

**Acceptance gate:** align question, keyed label, distractors and feedback; retain a valid concept binding; review the displayed block generated by the real factory; and add a focused regression that would fail for this unrelated keyed label. Subject review should confirm the numerical growth examples, rather than approving based on string length or the presence of a quiz.

## CR 002 — Bubble sort copy contradicts the scored space answer

Tracked follow-up: [BB-LRN-012 — issue 73](https://github.com/castlemilk/brainbuilder/issues/73).

**Exact source:** [challenge-bubble-impl](https://github.com/castlemilk/brainbuilder/blob/abf70fa012356038ffa5a2c4092584d452724e5e/packages/courseware/src/content/challenges.ts#L123-L178). Blocks `challenge-bubble-impl-trace`, `challenge-bubble-impl-lab` and `challenge-bubble-impl-check`.

**Reproduction:** inspect the trace, lab task and check together. The reference starts with `const a = [...arr]`. The lab asks for a new sorted array without mutating input. The keyed check option `opt-o1` says “O(1) in place,” and feedback says no second array is allocated. The deep [bubble-sort](https://github.com/castlemilk/brainbuilder/blob/abf70fa012356038ffa5a2c4092584d452724e5e/packages/courseware/src/content/sorting.ts#L16-L72) trace also copies its input.

**Expected:** the assessment must name which implementation and memory-accounting convention it asks about. A copied array proportional to input length must not be described as an in-place implementation using only scalar extra state. **Actual:** the visible code and required output behavior conflict with the scored explanation.

**Acceptance gate:** choose and state the mutation/output contract; reconcile code, lab task, examples, complexity question and feedback; distinguish the in-place algorithm variant from the provided copying implementation; and include a focused assertion on the displayed copy and its stated space cost. If the copying contract remains, separately verify that the original input is preserved and the returned sequence is sorted. Do not award general complexity understanding from three output examples alone.

## CR 003 — Jump search prose disagrees with its scan direction

Tracked follow-up: [BB-LRN-013 — issue 74](https://github.com/castlemilk/brainbuilder/issues/74).

**Exact source:** [jump-search](https://github.com/castlemilk/brainbuilder/blob/abf70fa012356038ffa5a2c4092584d452724e5e/packages/courseware/src/content/searching.ts#L91-L135). Blocks `jump-search-read` and `jump-search-trace`.

**Reproduction:** compare the third explanatory sentence with the second loop. The prose says it linear-scans backward to the previous jump point. The code starts at `prev` and increments `prev++` within the candidate block. On `[1,3,5,7,9,11,13,15,17]` with target `9`, block size 3 reaches the block ending at index 5, then checks index 3 followed by index 4: a forward scan.

**Expected:** explanation, trace points and code describe the same direction and block boundaries. **Actual:** the prose teaches a backward scan while the displayed code scans forward.

**Acceptance gate:** reconcile the prose with the intended implementation, trace the example above and one absent target, and state the block-size and bounds convention. Include empty input, a final short block and targets outside the value range in appropriate implementation checks before reusing the example as authoritative content.
